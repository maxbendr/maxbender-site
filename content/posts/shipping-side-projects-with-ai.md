In the last quarter I shipped three things I actually use: a content agent, a personal operating system, and a habit tracker that is rude to me on purpose. Here is what I would tell myself in December.

## Writing the code stopped being the bottleneck

With a model doing the typing, a working version of anything takes an evening. That changes which decisions matter. The hard parts are now scope, data, and whether you will still open the thing in three weeks.

I killed two other projects in the same quarter because they were fun to build and useless to use. That ratio feels about right.

## The demo to daily use gap is enormous

A project becomes real the day it runs without you babysitting it. Every one of mine needed the same boring work: a place to run, a way to see errors, and some memory of what happened yesterday.

That work is maybe ten percent of the code and ninety percent of the reason a side project survives.

## Constrain the model, then constrain it again

The output got good when I stopped asking for good output and started removing options. Fixed formats, short prompts, explicit rules about what not to do, and a second pass that only critiques. A model with a narrow job beats a model with a personality.

## Build for one user who complains loudly

Me, in this case. I know exactly what annoys me, I notice within a day when something breaks, and I never have to run a survey. Once the thing is genuinely useful to one person, deciding whether anyone else needs it is a much easier question.
